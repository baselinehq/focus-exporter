## Refactor: currency validation via golang.org/x/text/currency

Replaced the hardcoded `validCurrencyCodes` map with `golang.org/x/text/currency`. Ran `go get golang.org/x/text/currency@latest` (added golang.org/x/text v0.40.0 to go.mod, generated go.sum).

`isISO4217` in pkg/focus/validate.go now:
```go
func isISO4217(code string) bool {
	if code != strings.ToUpper(code) {
		return false
	}
	_, err := currency.ParseISO(code)
	return err == nil
}
```
Deleted the `validCurrencyCodes` map from pkg/focus/spec.go (no longer used).

Investigation note: `currency.ParseISO` alone is case-insensitive ("usd" parses to USD with no error), which contradicted the initial assumption that it was uppercase-only and broke the existing "lowercase currency rejected" test. Flagged this to the coordinator instead of changing the test expectation; the fix (an explicit `code != strings.ToUpper(code)` guard before calling ParseISO) was specified in response and applied, restoring FOCUS's uppercase-only currency code requirement.

Confirmed all four currency cases hold: USD valid, usd rejected (uppercase guard), Dollars rejected (ParseISO "not well-formed"), ZZZ rejected (ParseISO "not a recognized currency").
